# PR #6322 Review

**Title:** fix: regression which broke auto-destroying http requests
**Author:** slippedandmissed (Cause-App fork)
**Base → Head:** axios:v1.x...Cause-App:v1.x
**URL:** https://github.com/axios/axios/pull/6322

## Summary

This is a one-line surgical fix in `lib/adapters/http.js`. Inside the `handleResponse` callback that is passed to `transport.request()`, the guard that short-circuits response processing was changed from `if (req.destroyed) return;` to `if (req.aborted) return;`. The motivation is a Bun compatibility regression introduced in PR #4787: Bun's `node:http` implementation sets `autoDestroy: true` on requests by default (unlike Node.js, which defaults to `false`), which means `req.destroyed` is `true` the moment the response handler fires — causing every `axios(...)` call on Bun to silently hang, never resolving or rejecting. Reverting to the older `req.aborted` check restores correct behaviour on Bun while preserving the cancellation semantics on Node.js.

## Security Risks

None identified.

The change exclusively affects the early-exit guard in the HTTP response handler. Neither `req.aborted` nor `req.destroyed` involves user-supplied input, URL construction, credential handling, header manipulation, or prototype access. The property access is on Node's own `ClientRequest` object. Switching from `destroyed` to `aborted` does not widen any attack surface: an "aborted" request is one that has been explicitly cancelled (e.g. via `CancelToken` or `AbortController`), so the guard still prevents processing responses for intentionally-aborted requests.

One note for awareness (not a blocker): `req.aborted` was formally deprecated in Node.js v17.0.0 (the property still works but emits a deprecation notice in some environments). The longer-term fix may need to use `req.destroyed || req.aborted` or listen to the `'close'` / `'abort'` events directly; however this is an existing concern with the pre-#4787 codebase and is not introduced by this PR.

## Missing Tests

**Coverage gap — a regression test is absent.** The PR contains no additions to the `test/` directory. Given that the root cause is environment-specific (Bun's `autoDestroy: true` default), the ideal coverage would be:

1. A unit test that constructs a mock `ClientRequest` with `destroyed = true` but `aborted = false` and asserts that `handleResponse` does **not** return early — confirming the regression described in the PR body cannot recur.
2. The symmetrical case: `aborted = true` should still cause an early return (i.e. the guard still works for explicitly-cancelled requests).

Without these, a future refactor could silently re-introduce the bug. The existing CI suite does not run against Bun, so the regression was not caught automatically. A test is strongly recommended before merge.

## Breaking Changes

None identified.

- No public API signatures are altered.
- No exports are added or removed.
- Behaviour on standard Node.js is unchanged: `req.aborted` is `false` until the request is explicitly aborted, so the guard fires under exactly the same conditions as before PR #4787.
- The fix restores prior behaviour on Bun; nothing that previously worked on Bun stops working.
- The only observable difference is that promises for ordinary (non-aborted, non-destroyed) requests on Bun will now resolve correctly instead of hanging — a pure bug fix.

**Deprecation notice:** `ClientRequest.prototype.aborted` is deprecated in Node.js ≥ v17. This is pre-existing technical debt, not something introduced here, but the team should track it. A hardened version of the guard would be:

```js
if (req.destroyed || req.aborted) return;
```

which preserves the Bun fix while also covering the `destroyed` path for runtimes that set it deliberately after abort.

## Suggested Improvements

- Adopt the combined guard to fix the deprecation and keep both paths covered.

  **Code Fix:**

  ```js
  // lib/adapters/http.js — inside handleResponse
  if (req.destroyed || req.aborted) return;
  ```

- Add a regression test for the Bun `autoDestroy` scenario.

  **Code Fix:**

  // tests/unit/adapters/http.test.js

    const mockReq = new EventEmitter();

## Overall Assessment

**Request Changes** — The fix correctly diagnoses and addresses a real Bun regression, but it should ship with at least one regression test and ideally adopt the combined `req.destroyed || req.aborted` guard to avoid leaning on a deprecated Node.js property going forward.
