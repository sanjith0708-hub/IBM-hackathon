# PR #6349 Review

**Title:** fix(vulnerability): update follow-redirects to 1.15.6
**Author:** esezerguven
**Base → Head:** axios:v0.x...esezerguven:v0.x (3021e0d...4874926)

## Summary

This PR bumps the `follow-redirects` dependency from `^1.15.0` (resolved at 1.15.0) to `^1.15.6` (resolved at 1.15.6) in both `package.json` and `package-lock.json`, targeting the `v0.x` maintenance branch. The change is a direct response to [CVE-2024-28849 / GHSA-cxjh-pqwp-8mfp](https://github.com/advisories/GHSA-cxjh-pqwp-8mfp), which describes a credential-leak vulnerability in `follow-redirects` where HTTP `Authorization` and `Proxy-Authorization` headers were forwarded to a third-party host after a cross-origin redirect. No axios source files are modified; only the manifest and lockfile are updated. The PR was raised against the legacy `v0.x` branch (axios 0.28.x), mirroring the fix that was presumably already applied to `v1.x`.

## Security Risks

### CVE-2024-28849 — Addressed (positive finding)
The sole motivation of this PR is to remediate a **credential-leakage** vulnerability in `follow-redirects < 1.15.6`. Prior to 1.15.6, when a Node.js HTTP request followed a redirect to a different origin, `follow-redirects` failed to strip the `Authorization` and `Proxy-Authorization` request headers. An attacker who controlled an intermediate or destination URL (e.g., via an open redirect, a compromised CDN endpoint, or a malicious server returning 3xx) could harvest credentials passed by the caller. The upgrade to 1.15.6 ships the upstream fix for this behaviour.

### Lockfile integrity hashes verified as correct
Both the `resolved` URL and `integrity` (SRI sha512) values in `package-lock.json` match the official `follow-redirects@1.15.6` artifact on the npm registry:
- **URL:** `https://registry.npmjs.org/follow-redirects/-/follow-redirects-1.15.6.tgz`
- **Integrity:** `sha512-wWN62YITEaOpSK584EZXJafH1AGpO8RVgElfkuXbTOrPX4fIfOyEpW/CsiNd8JdYrAoOvafRTOEnvsO++qCqFA==`

No tampered or substituted hashes were introduced.

### Residual concern — semver range widens exposure window
The range is updated to `^1.15.6`, which will resolve to any future `1.x.y ≥ 1.15.6`. If a future `follow-redirects` release introduces a regression, dependents on the `v0.x` branch who re-run `npm install` will silently pull it in. Consider pinning to `>=1.15.6 <2.0.0` or accepting `^1.15.6` as acceptable caret-range practice (consistent with the existing policy in `package.json`). This is low risk for a security patch PR but worth noting for the maintenance policy.

### No new security surface introduced
The diff touches only `package.json` and `package-lock.json`. No axios source code, adapters, interceptors, XSRF guards, URL construction, or header-stripping logic is altered.

## Missing Tests

No test additions are included in this PR, which is **expected and acceptable** for a pure dependency version bump. The fix lives entirely within the `follow-redirects` package itself; the axios test suite cannot meaningfully unit-test the internal redirect-handling behaviour of an external module. The upstream `follow-redirects` 1.15.6 changelog and commit history confirm that regression tests covering the header-stripping behaviour were added there. Axios integration tests covering redirect scenarios (e.g., `test/unit/adapters/http.js` redirect coverage) continue to apply and should still pass without modification.

**Recommendation:** The maintainers may wish to add a CI check (e.g., `npm audit --audit-level=high`) to the `v0.x` branch workflow to catch future vulnerable transitive dependencies automatically, but this is out of scope for the PR itself.

## Breaking Changes

None identified.

- **API surface:** unchanged — no exported symbols, function signatures, or type definitions are modified.
- **Default behaviour:** unchanged — redirect handling semantics visible to axios callers are identical; the only behavioural delta is the security fix inside `follow-redirects` (headers are now correctly stripped on cross-origin redirects), which is the **intended** correction.
- **Node/browser compatibility:** unchanged — `follow-redirects` 1.15.6 maintains the same Node.js engine requirements as 1.15.0 and is not used in browser bundles (browsers use the XHR adapter).
- **Lockfile deduplication:** the lockfile records `follow-redirects` in two locations (the `node_modules/` flat tree entry and the legacy nested entry). Both are updated consistently from 1.15.0 → 1.15.6, so there is no version skew.
