# PR #6389 Review
**Title:** fix: using `RawAxiosHeaders` type cause compiler error
**Author:** ramram1048
**Base → Head:** v1.x...fix/type-headers-compile-error
**URL:** https://github.com/axios/axios/pull/6389

## Summary

This PR fixes a TypeScript compiler error (reported in issue #6369) that occurs when consumers import and use the `RawAxiosHeaders` type from axios. The root cause is that `RawAxiosHeaders` was declared as a module-local `interface` in `index.d.ts` and as a file-local `interface` in `index.d.cts`, but was never explicitly exported. Because TypeScript resolves `interface` declarations differently from `type` aliases in certain module contexts, referencing `RawAxiosHeaders` across module boundaries caused a "cannot be named" / "is not exported" compiler error for some consumers.

The fix has two parts:

1. **`index.d.ts`** — changes `interface RawAxiosHeaders` → `export interface RawAxiosHeaders`, making it a named export from the ESM declaration.
2. **`index.d.cts`** — removes the local `interface RawAxiosHeaders` declaration entirely and replaces all usages of the bare `RawAxiosHeaders` identifier with `axios.RawAxiosHeaders` (the namespaced version already exported from the `axios` namespace block inside the same file). This avoids the duplicate/shadowing problem that caused the compile error in CJS consumers.

## Breaking Changes

**None for well-behaved consumers — but one edge case worth noting.**

- The `export` keyword is added to `interface RawAxiosHeaders` in `index.d.ts`. This is a strictly additive change; any code that previously compiled will continue to compile.
- In `index.d.cts`, the local `interface RawAxiosHeaders` is removed and all references are replaced with `axios.RawAxiosHeaders`. This is a semantic no-op for runtime code, but any consumer who was relying on the *unqualified* `RawAxiosHeaders` name being in scope inside a `/// <reference>` import of `index.d.cts` may see a "cannot find name" error. In practice this is extremely unlikely — the typical usage is through `import type { RawAxiosHeaders } from 'axios'` which goes through `index.d.ts`, not the `.cts` file directly.
- No runtime JavaScript, exported symbols, function signatures, or Node/browser compatibility is affected.
